# 行情数据与口径

首页顺序固定为上证指数、深成指、创业板指、科创综指、科创50、沪深300、中证1000、证券板块、银行板块、半导体板块。成交额单位是亿元（元除以 100,000,000），放量/缩量分别表示相对上一交易日同期增加/减少，百分比以同期金额为分母。基数为 0 时仍可提供差额，百分比为空。

## 数据来源

| 行情 | 代码 | 来源 |
| --- | --- | --- |
| 七个指数（按上文顺序） | `sh000001`, `sz399001`, `sz399006`, `sh000680`, `sh000688`, `sh000300`, `sh000852` | 腾讯财经指数行情统计口径 |
| 沪深成交额 | `sh000002`（A 股指数）、`sz399107`（深证 A 指） | 腾讯财经上海 A 股 + 深圳 A 股，排除 B 股和北交所 |
| 证券板块、银行板块、半导体板块 | `881157`、`881155`、`881121` | 同花顺行业板块（证券、银行、半导体） |

腾讯使用[日分时接口](https://web.ifzq.gtimg.cn/appstock/app/day/query?code=sz399001)。实测含五个交易会话，`date` 是 `YYYYMMDD`，每个会话自己的 `prec` 是前收；每行第 4 列是**当日累计成交额（元）**，直接采用。七个指数金额遵循腾讯行情统计，例：实测深成指与同源深证综指的快照成交额一致，和深证 A 指略有差异，不能当作 500 只成分股独立统计。上海、深圳 A 股序列覆盖两个互斥市场，合计只取这两条序列的同日期同分钟；各项指数和板块相互重叠，不参与汇总。

行业板块改用同花顺，代码来自其[行业目录](https://q.10jqka.com.cn/thshy/detail/code/881272/)。当日分时取 `https://d.10jqka.com.cn/v6/time/bk_{代码}/last.js`：第 2 列点位，第 3 列是**单分钟成交额（元）**，`pre` 为前收。分钟历史取 `https://d.10jqka.com.cn/v6/line/bk_{代码}/60/{年份}.js`，第 1 列为 `YYYYMMDDHHMM`，第 5 列收盘点位，第 7 列单分钟成交额。实测年份文件包含最近约 40 个交易日，不能依赖全年无限历史。只将上一会话完整分钟存入进程缓存，每个板块每天成功下载一次；跨年时必要时补取上一年文件。历史缺失时显示当日行情，差额留空并在下次轮询重试。

同花顺行业分类与原东方财富分类不同，页面明确注明。旧源快照不会被标成新源，换源也不跨源计算差额。历史最新会话的收盘点位必须等于当日分时前收；分钟有缺口不计算同期差额。JSONP 仅剥离并校验请求路径对应的固定回调，不执行脚本。

2026-11-14 对三个板块真实取数：2026-11-13 对比 2026-11-12 收盘，证券成交额 **144.05147003 亿、缩量 15.29163999 亿**；银行 **385.4974 亿、放量 93.08461 亿**；半导体 **2317.572 亿、缩量 644.6967 亿**。三个板块的当日分时与分钟历史求和一致，与同花顺日线全天额最多相差几元（在回放覆盖的三日内最多 10 元），属于源字段精度差异。库内保留最近三日公共样本，以 10:00、11:30、15:00 验证同分钟比较。

这些公开接口未核实有版本或可用性承诺。Worker 只请求上述固定 HTTPS 端点、禁止重定向，每个品种每次网络尝试最多 4 秒（含 DNS 及历史请求），普通响应上限 256 KiB，同花顺分钟历史上限 4 MiB，传输失败最多重试一次。进程最多并行执行两个阻塞 DNS 查询，查询占满时请求快速失败。证券代码、名称、日期、分钟和数值均校验后才进入缓存。

## 时间与缓存

- 盘中取已返回的最新有效交易分钟，只与上一交易会话的同一时刻比较。周一通常比较周五；前日来自数据源的会话序列。基准日期为空或分钟窗口不完整时不计算差额。
- 09:30–11:30、13:01–15:00 是有效分钟；13:00 可出现在源数据中作为午后起始标记，午休和该标记不产生新的交易额。收盘后只比较完整交易日。若属于单分钟增量源且当日有缺行，累计额也不可用。
- 周末展示最近交易日。工作日开盘后没有当日行情时标明可能休市或数据源延迟；没有独立节假日历。获取时间和交易时间是两回事：拉取较迟、数据没有到达预期分钟或最新更新失败时，界面会标为已过期。
- Worker 首次启动立即尝试更新，盘中约每 60 秒，休市约每 15 分钟，接近开盘时缩短等待。SQLite 租约避免多个 Worker 同时轮询；网络调用期间不占用数据库事务。失败保留各项最近成功快照，沪深合计不会混用两个不同日期或分钟的来源。

## 接口与升级

`GET /api/market` 是无需登录的只读缓存接口。顶层 `source`、`source_url`（腾讯日分时入口）、`fetched_at`（最后成功获取的 Unix 秒或 null）、`stale`、`status`（`ready` / `partial` / `unavailable`）、`message` 描述快照状态。返回固定顺序的 `items` 和一项 `total`。

每项以 `key`、`name`、`code` 标识；`price`、`change_pct` 是点位和涨跌幅，`amount_yi`、`delta_yi`、`delta_pct` 是成交额、差额和百分比；未取得的数值为 null。`trade_date`、`as_of`、`previous_date` 分别为交易日、北京时间截止分钟、基准日期。`points` 为当日分时 [{time, price}]；合计只有成交额相关字段，走势图为空。`source`、`scope` 标注来源和范围；`status`、`message`、`fetched_at`、`stale` 描述该项是否可用及缓存状态。

Web 和 Worker 必须挂载同一 SQLite 卷，行情仅在 Worker 运行时更新。升级前按 [README 的备份步骤](../README.md#运维备份和升级)备份，随后执行 `docker compose up -d --build --wait`；若使用 DTK 共享网络，则执行 `docker compose -f compose.yaml -f deploy/notify.collector.yaml up -d --build --wait`。行情表在应用启动时创建，保留原记录、配置和密钥，部署没有额外环境变量。

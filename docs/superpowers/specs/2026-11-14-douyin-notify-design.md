# 抖音更新订阅系统设计稿

状态：用户于 2026-11-14 确认按推荐方案执行。实现与验证记录见对应计划及 verification.md。

## 目标与已确认选择

构建可通过 Docker Compose 部署的应用，监测多个抖音博主的视频更新，将视频语音转写成全文，生成 AI 总结，保存公开记录，并通过邮件通知多个订阅者。

用户已确认：同时支持自部署采集和第三方数据 API，优先使用自部署采集。

## 方案选择

推荐采用 Python FastAPI + 服务端模板及少量 JavaScript + SQLite + 独立后台任务进程。前台和后台同源提供服务，减少部署组件，适合单机多博主订阅。采集通过独立适配器接入自部署服务或第三方 API，转写和总结也采用独立接口。

备选方案一：前后端分离，使用 Vue + FastAPI + PostgreSQL + Redis；适合较大规模并发，但当前需求下增加部署和运维成本。

备选方案二：全量委托第三方采集和转写服务；资源占用较低，但增加外部服务依赖和使用费用，且不符合优先自部署的选择。

## 数据流与采集

1. 管理员添加博主主页地址或 sec_user_id，设置显示名称、启停状态、采集方式和检查间隔。
2. 后台任务按计划获取作品列表，按视频 ID 去重，解析真实发布时间；不能以抓取时间冒充发布时间。
3. 获取视频媒体，提取语音，生成全文；无音轨、无可识别语音或下载失败均明确记录原因，不以视频简介充当全文。
4. 使用当前启用的模型及提示词总结全文，长文本分段处理后合并总结。
5. 将完成的记录公开展示，为对应订阅者创建独立邮件投递任务。

默认每 10 分钟检查一次，可在后台调整，并限制最短间隔。首次添加博主时建立历史基线，默认仅监测之后的新视频；可明确选择补抓最近 N 条。首次初始化失败不能被记录为已完成。

自部署采集优先评估 Douyin_TikTok_Download_API，锁定实际接入版本并验证返回结构。后台支持配置服务地址、服务凭据及采集所需 Cookie，敏感配置不公开返回。Cookie 失效或平台限制需显示诊断状态，不能保证任意账号和网络环境下持续可抓取。

第三方接口支持配置 base URL、凭据及明确的 provider 类型。提供一种有文档和契约测试的通用 JSON 适配协议，覆盖作者标识、视频 ID、发布时间、标题、视频链接、媒体地址和分页游标。任意供应商的不同响应格式需要专用适配器，不能仅填 URL 就假设兼容。自部署采集失败默认报告失败，不自动调用可能付费的第三方服务。

## 转写和总结

默认使用本地 faster-whisper 转写，CPU 可运行，模型缓存持久化；同时提供兼容语音转写 API 的配置选项。部署文档说明本地模型下载与资源需求。

本版“内容全文”定义为视频可识别语音的完整转写，不包含画面 OCR、视觉描述和直播内容。保留段落，可附时间戳；不将 AI 改写后的文本当作原始全文。

后台支持多个总结模型配置：名称、base URL、model ID、API key、超时；全局选择一个启用模型。通过兼容 Chat Completions 的协议调用 DeepSeek 等服务。连通性测试执行最小实际请求，返回成功、耗时或脱敏错误。

提供默认中文总结提示词，可编辑覆盖并恢复默认。默认要求依据全文概括主题、核心观点与结论，不编造全文未包含的信息，区分作者观点和事实。每条记录保存生成时的模型标识和提示词版本，便于追溯。

## 展示与邮件的固定字段顺序

前台、详情页及 HTML/纯文本邮件的记录内容均严格按下列顺序展示：

1. 更新时间
2. 博主名称
3. 总结内容
4. 内容全文
5. 原视频标题
6. 原视频链接

“更新时间”定义为视频原始发布时间，界面以 Asia/Shanghai 展示，数据库保存统一时间。列表按发布时间降序排列，同一时间以稳定 ID 排序。前台提供分页、博主筛选及全文展开，折叠全文不改变上述顺序。

前台设计为简洁阅读列表，支持明暗主题切换并记住选择，初次跟随系统。桌面和移动端均可阅读，主页不出现后台登录入口。

## 后台与订阅者

后台固定为 `/admin`，密码登录。管理员初始密码通过部署环境配置，使用安全密码哈希保存；后台提供修改密码和退出。所有后台 API 都校验会话，加入登录限速、CSRF 防护及安全 Cookie 配置。隐藏入口不能替代鉴权。

后台管理博主、订阅者、采集设置、转写设置、总结模型、提示词、SMTP 和任务状态。订阅者由管理员添加，可接收全部博主或所选博主的通知，可单独启停。

SMTP 支持服务器、端口、用户名、密码、发件人及 TLS 模式配置，提供指定收件地址的测试发信按钮。每个订阅者单独发送，不暴露其他收件人的邮箱。通知包含全文，邮件 HTML 对外部文本转义。

## 任务可靠性与数据

持久化实体包括博主、视频记录、订阅者、订阅关系、模型配置、应用配置、处理任务及邮件投递记录。

各阶段独立记录状态和错误；失败任务采用有上限的退避重试，后台支持手动重试。任务通过租约领取，进程重启后能恢复超时任务。数据库对视频 ID 和“视频 + 订阅者”的投递记录施加唯一约束。

已发送给某个订阅者的通知不会因其他订阅者失败而整体重发。SMTP 在服务器接受后、应用保存状态前崩溃仍存在重复发送窗口；使用稳定 Message-ID 降低影响，不宣称严格仅投递一次。

API key、Cookie、SMTP 密码使用部署密钥加密存储，后台只显示是否配置，日志不输出原文。部署密钥与数据库一起备份但分别保管。媒体仅用于处理，默认处理完成后清理，并限制下载大小、时长、超时和重定向目标，防止无界资源占用及恶意媒体地址访问内网。

## Docker 部署

提供 Dockerfile、Compose 配置、环境变量示例和中文 README。Compose 分离 Web 和 Worker，挂载数据库目录与转写模型缓存；采集服务通过配套配置或已有实例接入，只暴露应用端口。

默认访问地址为 `http://服务器IP:8080/`，后台为 `http://服务器IP:8080/admin`，端口可配置。提供健康检查、自动重启和升级备份步骤。公开互联网部署时可在前方配置 HTTPS 反向代理。

## 验收

- 自动化验证前台和两种邮件格式的六字段顺序，以及时间倒序和分页。
- 验证多博主、分页采集、首次基线、重复视频、失败重试、重启恢复和多订阅者独立投递。
- 验证登录保护、无前台后台入口、秘密不外泄、模型切换/测试、提示词覆盖与恢复。
- 使用可控假服务验证采集、转写、总结和 SMTP 的处理链路及错误分支。
- 验证浏览器里的前后台操作、移动布局、主题切换和全文展开。
- 环境允许时构建 Docker 镜像并验证 Compose 启动和持久化。
- 真实抖音、真实模型和真实邮件的端到端验证需要用户实际配置；未获得凭据时应明确标记未验证，不能以模拟测试代替真实联调结论。
